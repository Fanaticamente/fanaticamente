# Project Architecture

- Professional marketplace visibility and record lifecycle use separate `marketplace_visible` and `deleted_at` fields so administrators can hide or archive profiles without losing internal data.
- Use Manrope for interface text and Sora for headings across all four systems; keep newspaper article copy in Georgia, and keep the shared small-text scale readable across responsive cards.
- Route transitions always reset document scrolling to the top because the application uses the browser window as its shared scroll container.
- Mobile page offsets must include `env(safe-area-inset-top)` only once: `body` already applies it in index.css, so page containers add plain fixed clearances below fixed headers; a second `env()` in flow content doubles the top spacing on iPhones.
- Static fan-facing interface copy is cataloged by the Vite fan-copy transform and edited through app_content overrides; dynamic account, article, score, and user content remain outside the text editor to preserve ownership and safety.
- Unsaved fan text previews use a tab-scoped sessionStorage draft read only with an explicit preview URL flag, so public content never changes before saving.
- Therapeutic team identity modes reuse the existing module visibility settings; circular color marks use a separate identity palette so corrected club colors do not alter interface themes.
- Legal acceptance evidence is written only server-side: signup acceptance comes from a server-created intent converted by an auth.users confirmation trigger, later acceptances via record-legal-acceptance; access is enforced by restrictive RLS policies using legal_acceptance_ok() and the shared edge legalGate, so never rely on the browser gate alone; history is immutable by trigger.
- Legal evidence IP comes only from `sb-forwarded-for` via `_shared/trustedIp.ts` (platform-set, overwrites client values), stored with `ip_source`, else NULL/"unavailable"; public legal pages and the acceptance window read `legal_document_versions` and record-legal-acceptance rejects (409) when the displayed `version_ids` differ from current, so shown text always equals the hashed version.
- Legal acceptance reports are generated and Ed25519-signed only server-side (generate-legal-report / verify-legal-report, shared `_shared/legalReport.ts`): the private key lives solely in the LEGAL_REPORT_SIGNING_KEY secret, the public key in `legal_report_keys`, signatures cover a canonical JSON manifest with SHA-256 of each file, and every generation/verification is appended to the immutable `legal_report_events` audit table; never build or sign reports in the browser.
- Public report verification runs only through the verify-public-report function and the /verificar-documento page: codes are 26-char Crockford base32 generated server-side and bound into the signed manifest, the registry (legal_report_registry) keeps report content immutable by trigger (only status/revocation fields may change), revocation goes through revoke-legal-report with mandatory reason, and public responses never include personal data.
- Legal acceptance integrity (Phase 5): every legal_acceptances insert is appended by trigger to the append-only legal_acceptance_chain (chain_hash = sha256(record_hash|prev_hash), genesis marked GENESIS:, serialized by advisory lock 727001); each entry and each report manifest gets an RFC 3161 trusted timestamp from an external TSA (FreeTSA primary, DigiCert fallback) stored raw in legal_chain_anchors — bytea must be written as "\x"-hex strings via PostgREST, never as byte arrays; stamping is best-effort/async (pending anchors retried by anchor-legal-chain, report generation, or new acceptances) and must never block or fail an acceptance; verify-legal-chain runs the server-side audit; never modify stamped anchors or chain rows (triggers forbid it).
